## Project preference — focused testing

Agreed on 12 November 2026: keep verification proportionate to save development time and assistant usage. Add meaningful tests with each feature and normally run only its affected tests. Small visual changes receive focused browser checks. Authentication, tenant access, security and shared business-logic changes may require checks across the affected features. Run the complete application suite at major milestones, merge/release checkpoints or when there is evidence of wider regression risk, rather than automatically after every feature or small fix. Explain broader runs briefly and avoid repeating passing checks without a relevant change or failure. Record actual verification and deferred coverage; documentation-only edits require document/format checks, not an application build or test suite. This preference governs future work and does not alter the historical verification results below.
